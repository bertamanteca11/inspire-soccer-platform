## Existing deployment workflow

`README.md`, `SETUP-FINAL.md` and `CAMBIOS_FASE_1.md` describe Vercel hosting and
automatic deployment after a GitHub push **if the repository is connected**.
There is no checked-in Vercel project binding, `vercel.json`, or deployment CI
workflow. The live project's Git connection, production branch and environment
scopes must be confirmed in Vercel before an approved push.

Current local branch: `feature/statistics-fixes`.

Use the existing Vite project settings:

- Project root: repository root.
- Install: `npm ci` using the reviewed lockfile; SheetJS comes from its pinned
  official distribution URL and must be reachable at build time.
- Build: `npm run build` (`tsc -b && vite build`).
- Output directory: `dist` (generated by Vercel, not added to this staging set).
- Local verification used Node 22.20.0. Ensure the hosted Node version satisfies
  the lockfile engine requirements; Playwright additionally requires Node >=20.
- Required build-time environment variables: `VITE_SUPABASE_URL` and
  `VITE_SUPABASE_ANON_KEY`, pointing to the already validated Supabase project.
  Both are browser/public configuration. No service-role key or user password.
  Vite embeds these values at build time; preserve the correct Vercel environment
  scopes. There are no additional VEO environment variables.
- `DEV_BYPASS_LOGIN` remains `false`.

## Approval and release sequence

1. Review the staged file list and final validation results. `.env` was already
   tracked: remove it from the index while retaining the local file. The ignore
   rules exclude environment variants, private spreadsheets and generated output.
   This does not remove files from older Git history.
2. Obtain explicit approval to commit. No commit, push or deployment is authorized
   by this handoff. A push may trigger Vercel automatically, so obtain deployment
   approval and verify the target branch/project before pushing or merging.
3. After approval, commit the reviewed staging set on the current branch and use
   the existing GitHub/Vercel release route for the confirmed production branch.
   Vercel installs and builds the source; do not upload local Excel or `.env`.
4. On the deployed HTTPS URL, open `/?veo=1`, sign in as admin, reload, and verify
   J5's 23 observations, 1,089 minutes and EUR 30 breakdown across the five sections.
   Confirm coach read-only behavior, viewer denial and signed-out login. Do not
   publish, correct or withdraw the existing match merely to smoke-test release.

No migrations, production writes, operational-record changes, commit, push or
deployment are part of this repository preparation.
